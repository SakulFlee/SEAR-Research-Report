\labeledsection{Methods}
To prove our hypothesis, we first create a simple experiment and demonstrate the techniques of \textit{dependency-injection}.
Based on this, we then try to estimate the security risk of an application utilizing \textit{dependency-injection} versus one that does not.

For the experiment, we will implement a plugin system in \texttt{Java}.
The plugin system will be capable of loading (i.e.~injecting) plugins into a running application.
To keep the application simple, we will only create and load one plugin.
Said plugin does only perform an effortless task (such as printing a message to the console), as we use it to demonstrate how one can implement \textit{dependency-injection} into an application.
This plugin will depend on a defined Plugin API to give a common point of reference for both the plugin and the plugin system.

The ultimate goal of this experiment is to demonstrate and explain how \textit{dependency-injection} can be used to extend applications dynamically and what risks come with it.
Furthermore, with the acquired knowledge, a more exceptional picture of risks and threats about the overall \textit{dependency-injection} topic can be made.
